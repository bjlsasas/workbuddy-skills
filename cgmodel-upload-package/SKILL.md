# CG模型网 上传包整理

把散落在磁盘上的模型文件夹 → 一个可直接拖进上传页的合规包。**不渲染**（视口截图即可，除非用户明确要求渲染）。

> 📘 **完整作业手册（给别的 AI 执行用）**：`E:\文件整理\南京地铁_上传包\_通用流程\CG模型网上传包_标准作业流程SOP.md`
> 含变量表、环境坑、逐步流程、脚本清单与参数替换点、验收 checklist、踩坑速查表。
> 可复用脚本在同目录 `脚本\`（换站需替换硬编码路径）。本技能是精简版；**要交付给别人执行时优先发那份 SOP**。



## 平台硬规则（会变，动手前核对一次）

- 预览图：**按 CG模型网平台类别，每类 2–3 张，合计约 8–10 张**（正图 3–4 + 室内 2 + 边面线框 ×2（透视/俯视）+ 视口点面信息截图 1–2）；**不再固定 13 张**（用户 2026-09-21 改，已交付的珠江路/交院/百家湖维持原样不返工）
  **线框图一律「明暗处理 + 边面（Edged Faces）」并开着视口面数统计**（纯线框一律返工）；
  禁文字 / 联系方式 / 二维码 / 水印；**最小边 ≥1060 px**
- **建筑 / 室内外 / 地形 / 场景类豁免**：前景可触及画面边界，封面须填满不留白 — 直接出大图
- 附件：`.max / .obj / .ma / .c4d / .fbx`，仅 zip/rar/7z，**每包 ≤1G**，**平级目录无子文件夹**，不设密码
- 价格自主定价 ≥¥10
- 必填项：面数/点数、布线类型（面片 / 三角+四边 / 四边 / 三角 / 多边形）、绑定动画、材质、贴图（**映射方式 + UV 类型**）、未塌陷、可打印、使用插件

> 「贴图映射方式」和「UV 类型」是售后重灾区。UV 类型从 未展开/重叠/不重叠/混合 里选。
> **⚠️ 南京地铁这批模型：用户定死一律填「重叠」，不实测**（站厅全是平铺砖墙/地砖/天花，UV 岛必然复用 0–1）。
> **严禁写 UV 采样脚本**：逐面 `meshop.getMapFace/getMapVert` 会把 Max 锁死（交院站 19.6 万面 → 卡 4 小时只能强杀），MAXScript 无超时不可中断。

## 工作流

### 1. 摸清资产（无损，只读）

列出目录：文件数、按扩展名分组、总大小。判断贴图文件夹是否已经是平级结构（多数成品资源包已经是，正好符合平台要求）。

区分**预览图**与**贴图**：贴图尺寸通常 512–2048，缩略图尺寸（64–512 且长宽比夸张）不是可用预览图。

> ⚠️ **一个文件夹里出现多个 `.max` 时：只处理一个，取「第一个」，其余全部忽略**（用户明确要求）。
> 成品资源包常塞着备份版 / 老版本 / 分块版（如 `xxx.max`、`xxx_1.max`、`xxx_改.max`），
> 逐个处理会得到多套命名、多份 zip，最后还要用户做取舍 —— 这就是用户不想看到的。
> - 「第一个」= 按**文件名自然排序**（PowerShell `Sort-Object Name`）取首个；不要按体积/时间挑，别自作聪明选"看起来最新的"
> - **不要进 `Autobak` / `maxback` / `sceneassets` 等备份目录**找 max，只认目标文件夹**根层**
> - 开工前先向用户**报一句选了哪个、跳过了哪几个**，避免他以为漏了
> - 输出命名里的资产名跟着选中的那个 `.max` 走（`WXA2133.max` → 站码 `WXA2133`）

### 2. 打开场景，取必填参数

在已连接的 Max 实例上 `loadMaxFile` 目标文件（即上一步选中的**唯一**那个），然后一次取证：

> ⚠️ **面数与布线类型必须在 Poly 层统计，不要在 mesh 层。**
> 成品场景几乎全是 **Editable_Poly**，而 `o.mesh` 返回的是**已三角化**的网格 —— 用它统计会把
> 「四边面为主」误判成「100% 三角面」，面数也会虚高（实测同一场景：mesh 层 175,189 面 vs
> Poly 层 80,239 面，差 2.2 倍）。用错口径会直接写错平台必填项，属退款高危。

| 要拿的 | 取法 |
|---|---|
| 对象数 | `objects` 里 `superClassOf o == GeometryClass` 的个数 |
| **面数（填表用）** | Editable_Poly → `polyop.getNumFaces o`；Editable_Mesh → `o.mesh.numfaces`。此值与 Max 视口统计一致 |
| 面数（三角化后） | `o.mesh.numfaces` 累加 —— 只在描述里作为补充说明 |
| 点数 | Editable_Poly → `polyop.getNumVerts o`；Mesh → `o.mesh.numverts` |
| 布线类型 | Editable_Poly → `polyop.getFaceDeg o f` 统计 3 / 4 / >4 分布；Mesh → `meshop.getVertsUsingFace msh #{f}` 的 `numberset`。**不要用 `getFaceDegree`**（不存在） |
| 场景对象类型分布 | `classof o`（确认是否全为 Editable_Poly，决定上面用哪套 API） |
| 修改器 | `o.modifiers.count`；全 0 → 未塌陷=否，无需修改器截图 |
| 绑定 / 动画 | `o.isAnimated` |
| 材质数 | `scenematerials` |
| 贴图数 + 路径 | 用**显式栈循环**遍历 `scenematerials` + 多维子材质的 `materialList`，收集 `BitmapTexture.filename` 去重 |
| UV 通道 | `bitmapTex.coords.mapChannel` 去重 |
| UV（关于UV） | **一律填「重叠」，不实测，不许写采样脚本**（会把 Max 跑死，见上行警告） |

### 3. 修贴图路径 → 相对路径

成品资源包的 `.max` 常把贴图指向原作者机器（如 `D:\xxx\...`），**全部失效**。按 basename 与本地文件夹匹配，命中后改写：

```
bitmapTex.filename = (getFilenameFile f) + (getFilenameType f)   -- 只留文件名
saveMaxFile <包目录>/WXA2133.max quiet:true
```

- 匹配前先统计「引用的唯一贴图数 vs 本地文件数」，不匹配的要单独报给用户
- 存进包目录后 **必须验证**：`loadMaxFile path missingExtFilesList:&ml`，`ml` 为空（返回 `undefined`）才算通过
- **绝不覆盖原始 `.max`**，只输出到包目录

### 3b. 命名规范化（对象 / 材质 / 贴图）—— 用户明确要求，每包都要做

成品资源包的命名几乎总是垃圾：对象名是原始编号，材质名是**几十个来源名拼接的超长串**
（含 `Box478`、`Material #173865`、`对象025`、甚至其它项目的残留编号），
贴图有一半是纯流水号。用户明确要求「重新命名，且规则要能复用到其他站」。

**规则 v1（已落地验证）**

```
对象： {STN}_{CAT}_{NNN}                 M1_ZJL_EQPM_012
材质： MT_{STN}_{CAT}_{NNN}              MT_M1_ZJL_EQPM_012
贴图： TX_{STN}_{CAT}_{NNN}_{CH}[_n].ext TX_M1_ZJL_EQPM_012_D.tga

STN = {线号}_{站名罗马字缩写}   M1=地铁1号线, ZJL=珠江路 ZhuJiangLu
CH  = D 漫反射(slot2) / E 自发光(slot6) / O 不透明 / B 凹凸 / R 反射 / N 法线
NNN = 同类内 3 位序号，按「原族号 + 原序号」升序 —— 保证可复现
```

全大写 + 下划线，**无中文、无空格、无特殊字符**（跨平台导入不乱码）。三层严格对齐，
材质/贴图一眼看出归属谁。

**CAT 语义类别怎么定（不要瞎猜，用实测几何）**

1. 先按原对象名的「设计族号」分组（如 `XWA2133` + `XG227` + `C0108`，族号 = 第 8–12 字符）
2. 统计每族的：个数、面数、**典型尺寸 XYZ**、中心标高、**Z 范围（是否跨层）**
3. 据此判类别。典型判据：
   - 水平超大 + 厚度 < 50cm → `FLOR` 地面铺装
   - 竖向大面、跨层 → `WALL` 墙体
   - 大体量、跨层 → `ARCH` 土建结构
   - 倾斜长条 + 跨层 → `ESC` 扶梯
   - 竖向井道、层高 > 10m → `ELEV` 电梯井
   - 高处薄板 → `SIGN` 标识；高处小件 → `LAMP` 灯具
   - 极细长条 → `PIPE` 管线
   - 1m 级块状 → `EQPM` 设备；< 1m 小件 → `PROP` 道具
   - **拿不准的一律用上位概念**（`EQPM`/`MSC`），并在交付文档里标注「推测」
4. 类别字典固定：`ARCH FLOR WALL ELEV ESC SIGN LAMP EQPM FURN PROP PIPE MSC`
5. 把「族号 → 类别」映射表写进交付文档（买家可查，其他站可直接复用同一张表，
   同一来源的模型族号体系是一致的）

**执行顺序（关键）**

1. Max 导出清单（`OBJ|名|材质名|面数|中心|尺寸`、`MAT|名|类|子数`、`BMP|贴图|顶层材质|子材质|slot`）
2. **Python 算映射**：优先用**实际引用链**溯源，不要用文件名前缀猜 ——
   - 材质 → 用它的对象（`o.material == 该材质`），准确率 100%
   - 贴图 → 其所属顶层材质 → 用该材质的对象，准确率 100%
   （实测：名字前缀猜测只有 20/292 命中，实际引用链 292/292）
3. Python 输出 `map_obj.tsv / map_mat.tsv / map_tex.tsv`（tab 分隔，放**纯 ASCII 路径**）
4. Max 读表改名（对象 → 材质 → 贴图 filename）
5. Python 在打包目录 rename 贴图文件（建议从原盘**重建**暂存目录，避免状态漂移）
6. `saveMaxFile` → `loadMaxFile missingExtFilesList` 验证 `= 0` → 再导出 FBX

**踩过的坑**

- **同一张贴图被多个材质槽复用**（实测 2666 个引用 vs 594 个文件）：遍历时会重复处理，
  第二次用「新名」去查「旧名表」必然 miss。判据要加上「已是新名则跳过」，
  否则会误报上千个 false miss。
- **场景残留陈旧绝对路径**：个别 bitmap 仍指向早已移走的目录。编号时必须按
  `os.path.basename` 判定「同一张磁盘文件」，否则同一个文件编两个号 → **最终丢一张图**。
- `readLine` 在这个 Max 环境**可用**（`while not eof f do (readLine f)`）；
  用 `filterString ln "\t"` 拆 tab。脚本整体要包在 `( )` 里（顶层不许 `local`）。
- 改完名 `.max` 文件名也一起改（如 `M1_ZJL.max` / `M1_ZJL.fbx`），与内部命名体系统一。

### 4. 视口截图（不渲染）

> ⚠️ **动手截图前，先把视口照明切成「用场景灯光照亮」**（视口标签 `[标准]` → 照明和阴影 → 用场景灯光照亮）。
> 默认的「用默认灯光照亮」模式下 Nitrous **不会把贴图上屏** —— 拍出来全是灰白素模，
> 哪怕材质挂了图、贴图路径可解析、UV 正常、`showTextureMap` 返回成功也没用。
> 切到「用场景灯光照亮」后贴图立刻显示，画面同时明显变亮，一次性解决「素模」+「室内太黑」两个问题。
> 该菜单**在 MAXScript 里无接口**（`viewport` 的 85 个方法里没有、`NitrousGraphicsManager` 的 15 个属性里没有、
> `actionMan.getTable` / `viewportLabelMenu` 均不存在）→ 只能用 UI 自动化点击，
> 做法见 `3dsmax-mcp` 技能的 *Viewport label menu* 一节。
>
> ⚠️ **2026-09-21 补充（百家湖站实测）**：
> - 该菜单项在**浮动代理面板**里是**灰的（disabled）** —— 面板不给切（实测两次）。
>   主视口里则**可用且默认已勾选**。所以走代理面板拍照时这条路用不上（好在面板默认已继承该模式）。
> - **室内仍然黑，别只怪照明模式**：本例站厅发暗的真正原因是**几何本身是未受光的单面壳体背面**
>   （吊顶铝板、墙面从内部看全是背光面）。三层验证：① `backgroundColor` 改洋红后黑区**依旧黑** → 黑的不是背景；
>   ② 向上打射线命中的是某个「材质里并无黑色漫反射」的构件 → 是背光面；
>   ③ 加 ×1000 盏场景灯**毫无变化**（46.0 → 45.9，该模式不理场景灯）。→ 三条都指向背光面，而非照明开关。
> - **解法：临时把所有叶材质的 `selfIllumAmount` 拉到 85**（栈循环展开多维子材质的 `materialList`，
>   本例 1,997 个叶材质一次设完）。吊顶、铝板、导向牌立刻显色，站厅达到可交付亮度；
>   顺带**满足「室内截图去除阴影」**（全自发光即无投影）。
>   ⚠️ **交付前必须把自发光还原为工程原值 0**，并自检 `leafSelfIllumNonZero == 0`
>   —— 改的是将要交付的那个 `.max`，很容易忘。
> - 同时确认**「线框覆盖」复选项没被勾上**（勾上会把整屏压成洋红网线、并让「照明和阴影」各项置灰）。

用连接器的 `set_viewport` + `capture_viewport`，**不要手搓 MAXScript 抓图**：

```
set_viewport(view="perspective", eye=[...], target=[...], fov=45,
             padding=1.15, shading="smooth")
capture_viewport(max_width=1600, source="active", capture_method="auto")
```

- **`capture_method`**：⚠️ **2026-09-21 实测修正** —— `auto`（nitrous_dib）与 `window`（print_window）
  在本环境下**都会带上 UI 层**（标题条 + 水印 + 统计）。所以「干净的美图」**不能靠换 method 得到**，
  **必须在拍之前把左上角统计关掉**（key7 是切换键）；出统计图时再打开。两种 method 抓的图都要裁顶部。
- `frame_names` 传 **2 个处于包围盒两端的节点名**即可贴合，无需传全部
- ⚠️ `frame_names` 会把**透视**视图缩得偏小；想要填满画面的透视构图，**去掉 `frame_names`，只给 `eye`/`target` 并手动调 `eye` 距离**
- 轴向视图用 `view="front"|"back"|"left"|"right"`，配 `frame_names` 才贴合，否则正交 zoom 会框得极宽；纯正上方俯视用 `view="orthographic"` + `eye` 在目标正上方
- ⛔ **线框/布线图不要用 `shading="wireframe"`** —— 非渲染视口下纯线框只有细线，深色背景上对比度极低
  （实测亮线像素仅 **0.46%**，整张图等于空白，会被拒收）。改用 `shading="smooth"` + **`edges=true`**
  （= 明暗处理 + **边面 / Edged Faces**），亮部占比可达约 **51%**，且**同屏开启面数统计**（见第 5 节）
- `capture_multi_view` 可一次出 2×2 拼图（参数里**没有** `frame_names`）

### 4b. 室内 / 人视角度取景（可选，但对建筑室内类转化最好）

用户常会额外要"一张室内角度的图"。**不要凭感觉猜眼高**——建筑模型大多是被缩放过的，猜错会拍出一堆"像在室外"的废图。按下面顺序做：

1. **先定量：找楼面标高。**
   列出所有物体的 `o.min.z` / `o.max.z`，找**人机尺度的小物件**（闸机、栏杆、标识牌、消防箱）。
   这类物体通常高约 **200 单位**左右，它们的**底面 z 基本就是站厅楼面**。
   本案例：闸机 `z=[20,338]`，高 212 → 楼面 Z≈0（而不是整体包围盒底部的 -570，那是下层结构顶板）。

1b. **更准的做法：从候选机位打射线，直接量出「脚下地板 / 头顶天花 / 四周多远有东西」。**
   `intersectRayScene` 一次就能给出答案，比从包围盒猜标高贵得多（本案例靠它才发现站厅是
   **分层**的：地面 z≈17.5、站厅楼面 z≈25.7、其上顶棚 z≈28.7、再往上 9.5 单位才是大屋顶，共三层）：
   ```
   -- 注意：intersectRayScene 返回的是 #(node, ray) 二元组数组，不是 RayMeshHit！
   for h in (intersectRayScene (ray eye dir)) do (
     local hp = if classof h == Array then h[2].pos else h.pos
     local hn = if classof h == Array then h[1].name else h.node.name
   )
   ```
   - 向下打 → 得到**真实楼面标高**（比小物件法更直接）；向上打 → 得到**天花/雨棚标高**（净高 = 两者之差）。
   - 水平打 ±主轴（PCA 特征向量）→ 得到**可站空间进深**；某方向返回 `undefined` 说明那边是敞开的
     （露台/线路侧），**这种方向别当主视角**，打出去就是黑背景。
   - ⚠️ 每次 `intersectRayScene` 约 **0.7~1 s**（407 个物体、无空间加速），一轮探测控制在 **≤120 条射线**，
     别开大网格搜索，否则一次要十几分钟。
   - 眼高 = 楼面 + **1.5~2 单位**；某站点实测 `eye z=27.3`（楼面 25.7）正是人眼高度。
2. **眼高**：楼面 + **150~300** 单位（模型里约等于 1.5~3 m）。取 250~300 会让地面占比更大，少吃空白背景。
3. **看不见内壁？把材质设成双面。**
   建筑壳体的面多朝外，视口从内部看会被背面剔除，画面直接"穿透"成室外。
   属性名是 **`twoSided`**（不是 `backfaceCull`，后者在 MAXScript 里取不到）：
   ```
   for s in <所有子材质> do ( try ( s.twoSided = true ) catch() )
   ```
   注意：**多维子材质本身没有 `twoSided`**，要展开到 `materialList` 的子材质去设（本案例 1327 个子材质设成功、291 个多维材质跳过）。
4. **站位：挑"设备密集区"，别沿长轴纵深。**
   地铁站厅这类模型只有局部有细节，站在中轴线上往远处拍只会得到空旷楼板 + 远景体块。
   正确做法是**靠近服务亭 / 闸机 / 立柱**，用**两根立柱做前景框景**，把主题物放画面正中。
   本案例最佳机位：`eye=[60100,72300,290]` → `target=[61900,81700,-260]`，`fov=80`（广角是室内感的关键，55~65 太窄）。
5. **距离**：主体离相机 **4~8 单位（米）**。贴到 2 m 以内会糊/被裁切，本次就废了一张。
6. **如果切了「用场景灯光照亮」室内仍然发暗、发平**，说明**场景里真的一盏灯都没有**
   （先 `for o in objects where superClassOf o == light collect o` 数一下，再查 `hideByCategory.lights`
   和 `ambientColor`）。这种场景下画面靠自发光/环境色，属于该模式能达到的上限；
   想让吊顶和地面有明暗层次就必须布灯 —— 先问用户，别擅自建灯。
7. **收尾**：视口截图顶部会带 Max 菜单条，**裁掉顶部 20~30 px**，再用 LANCZOS **等比放大到最小边 1060**（满足平台 ≥1000 px）。
   上方/侧面的大片黑色是视口世界背景（模型无吊顶 / 无灯时的必然结果），属可接受范围。
7b. **不许用「全选 + Zoom Extents」定取景**（用户明确要求：「截图的时候不要全选」）——
   全选会污染选择集、也会把取景交给整体包围盒而不是你想拍的空间。
   改成：模型主轴（对 407 个物体包围盒角点做 PCA 得 E0/E1/Z）+ 射线探测逐机位安放 `eye/target/fov`。
   ⚠️ 模型常在**世界坐标里被旋转过**（本例约 829°），**世界 X/Y 与模型长/宽不对应**，
   正交视图的「方向」必须用主轴向量算，不能直接拿 ±X/±Y 当长立面。
7c. **亮度自检（用户会挑）**：截图灰度均值应落到**室外图同一档（约 60~80）**。
   旧版室内图均值只有 **33~41**、暗部(<20)占 39%~47%，会被直接判「太暗」退回；
   关掉阴影后重截，均值升到 **61~79**（提升 1.8~2.1 倍）才算过关。
   注意「抬头上看」这类视角通常最暗（天花板基本无直接光照，实测均值只有 28），
   宁可拍**接近水平**的机位，也别为了构图把画面大半让给未受光的顶棚。

8. 命名建议 `10_室内视角_…` / `11_室内视角_…` / `12_室内视角_…`，一个室内角度出一张；
   并在参数表里注明"人视高度"，让买家知道这是实拍式视角而非渲染图。

### 5. 「视口点面信息截图」（平台必填）

**首选做法：直接用 3ds Max 自带的视口统计（快捷键 7），零后期、原汁原味。**

1. **开统计** —— 对应快捷键 **7**，投给**活动视口的那个窗口**：
   - 主视口：`windows.postMessage (windows.getMAXHWND()) 256 55 0x00080001` / `257 55 0xC0080001`
   - **浮动代理视口：要发给面板内的 `ViewPanel` 子窗口**（`EnumChildWindows` 递归找 class=="ViewPanel"），
     ⚠️ 发给面板顶层窗口或 Max 主窗口**都无效** —— 详见 5b-3。
   ```
   hw = windows.getMAXHWND()
   windows.postMessage hw 256 55 0x00080001   -- WM_KEYDOWN  VK_7('7'=55, scancode 0x08)
   windows.postMessage hw 257 55 0xC0080001   -- WM_KEYUP
   ```
   开启后视口左上角显示：`总计 / 多边形: xx,xxx / 顶点: xx,xxx / FPS: x`
   > 别去 `viewport` 结构体或 `NitrousGraphicsManager` 里找统计开关属性 —— **都没有**（已拉全表核对：
   > `viewport` 只有 `SetShowEdgeFaces`/`GetShowEdgeFaces`，无任何 statistics 方法）；
   > `actionMan.getTable` 也不存在。模拟按键是唯一且已验证可行的路。
   > **状态判据要用白字占比，不要用灰度极差**（视口有亮内容时关着也有 154）。
2. **截图** —— `capture_viewport(capture_method="window")`，窗口捕获才带得上这行统计。
3. **用完关掉** —— 统计是**每视口**的状态，拍完再按一次 7 复位。
   （⚠️ 本环境下 `auto` **同样会带 UI**，想拿干净图只能**拍前把统计关掉**，不是换 method。）

> ⚠️ **坑 1：`多边形 / 顶点` 统计的是「画进画面里的」**。
> 如果机位只框住模型的一部分，统计数就会**小于场景总数**，和参数表里填的数字对不上（买家一比就露）。
> 出 08 前**必须让整模型落进视锥**：取世界包围盒 8 个角点，按**当前视口的真实宽高比**
> （`th = tan(fovH/2)`、`tv = th / aspect`，注意 `c.fov` 是**水平** FOV）解一个能全包住的相机距离 D。
> 视口宽高比一变（本例 1050×791 → 1176×791），原来算好的 D 就可能**竖向裁切**，要重算。
> 出图后自检：场景总数（`polyop` 求和）应恰好等于图上数字。

> ⚠️ **坑 2：`set_viewport(source="active")` 改不动「用户透视视图」的机位** —— 它只切视图类型
> （返回 `view_persp_user`），`eye/target` 不生效，拍出来还是旧视角。要给主视口定位，走 MAXScript：
> ```
> local c = getNodeByName "ZZCAM_C"
> if c == undefined do c = TargetCamera name:"ZZCAM_C"
> local t = getNodeByName "ZZCAM_T"
> if t == undefined do t = TargetObject name:"ZZCAM_T"
> c.target = t
> t.pos = <target>;  c.pos = <eye>;  c.fov = <fovH>
> viewport.setCamera c;  viewport.setTargetObject t;  viewport.setType #view_camera
> ```
> 拍完还原：`viewport.setType #view_persp_user` 再 `delete` 掉这两个临时节点。

#### 5c. 代理视口的 6 个环境坑（2026-09-21 百家湖站实测）

1. **主窗口最小化 → 代理视口停止重绘**，报 `AGENT VIEWPORT has not redrawn` /
   `must remain visible for fresh Nitrous captures`。这不是面板的问题，是 **Max 主窗口被最小化**了
   （`IsIconic(MAXHWND) == 1`）。修：外部 Python `ShowWindow(MAXHWND, 9 /*SW_RESTORE*/)` + `BringWindowToTop`。
   点面板 / 发按键等操作都可能把主窗口带成最小化，**每次抓图前先检查一次**。
   （注：只有**抓图**受影响；开统计已改成 PostMessage，不受焦点/最小化影响。）
2. **面板开出来可能很小**（980px）或跑出屏幕。`agent_viewport(action="open", width=…, height=…)` 的尺寸
   **不一定生效**；可靠做法是外部 Python 找到面板内的 **类名为 `ViewPanel`** 的子窗口
   （其父为 `Qt653QWindowIcon`），用 `SetWindowPos` 直接撑大（实测撑到 1766×981）。
   窗口层级：`AGENT VIEWPORT` → `Qt653QWindowIcon` → `Qt653QWindowIcon` → **`ViewPanel`** → 若干 `Label`
   ← 这棵树同时也给出 key7 的正确投递目标（5b-3），一次 `EnumChildWindows` 两件事都办了。
3. **临时相机的显示图形会在视口里画绿线 / 绿色方框**（`ZZCAM_C` 的机身 + 目标连线）。俯视、低仰角时特别明显，
   会毁图。**拍之前把 `ZZCAM_C` / `ZZCAM_T` 设 `isHidden = true`**，或干脆删掉。
   排查法：`for o in geometry do o.isHidden = true` 后绿线仍在 → 一定不是几何体，而是相机显示图形。
4. **`viewport.SetTM` 能让视图绕视线轴旋转** —— 正交顶视想「长轴横放」就靠它。⚠️ `viewport.*` 均作用于
   **Max 的活动视口**，所以要先 `set_viewport(source="agent", ...)` 让代理视口成为活动视口
   （`agent_viewport(action="zoom"/"frame")` 用的是 MCP 自己的目标，不受此限）：
   ```maxscript
   local tm = viewport.GetTM()
   viewport.SetTM (matrix3 [0,1,0] [-1,0,0] [0,0,1] tm.row4)   -- 顶视旋转 90°
   ```
   ⚠️ 旋转后视图会**偏移**（`row4` 语义随基向量变）→ 紧接着调一次 `agent_viewport(action="frame")` 重新居中；
   实测 **`frame` 不会重置方向**，两者配合正好。
   ℹ️ 顺便记一条：**点面板并不会把键盘焦点交给它**（`windows.getFocus()` 仍是主视口的 Label），
   所以 `viewport.*` 生效与否别拿"点过面板"当保证 —— 改完先抓一张确认。
5. **`viewport.Zoom <1` 放大、`>1` 缩小**（同样作用于活动视口）。但正交视口的取景受**屏幕分辨率物理限制**：
   想出一张「最小边 1060」的横长平面图，内容高度至少要占 1060 px，而面板高只有 ~980 px ——
   **正交顶视 + 裁切做不出达标的横长图**（内容裁出来最小边只有 300~600 px，放大 2~4 倍必糊）。
   这类「平面布局图」应改用**斜俯视**（让长轴沿画幅对角线铺满）才够分辨率。
6. **边面的颜色 = 每个物体的 `wirecolor`**。模型自带线框色五花八门（洋红 / 青 / 橙），一开边面整栋楼变艳色。
   **拍前统一压暗、拍完还原**：
   ```maxscript
   -- 拍前：原色存 txt，再统一
   for o in geometry do ( format "%|%|%|%\n" o.name o.wirecolor.r o.wirecolor.g o.wirecolor.b to:f; o.wirecolor = color 25 25 25 )
   -- 拍完：读表还原（367/367 实测）
   ```
   另：`viewport.SetShowEdgeFaces true` / `GetShowEdgeFaces()` **在 MAXScript 里可用**，不必走 UI 菜单勾「边面」。

#### 5d. 「地面广场 + 地下站厅」两层模型，俯视线框图怎么拍

正上方俯视**只能看到地面面层**（百家湖 `JND4005_001`：一块 98×250 的广场板），地下站厅被整个盖住 ——
拍出来是一大片没有内部结构的草地，等于废图。

**做法：把广场面层「临时下移」而不是隐藏**（`move o [0,0,-30]`）：
- **隐藏** → 它掉出视口统计，图上数字比全场景**少**（本例 93,457 → 93,434），与参数表对不上；
- **下移** → 仍落在视锥内、**照常被统计**，图上数字与全场景、与 08 完全一致（实测 93,457 / 116,748），零破绽；
  同时站厅布线完全露出，线框图信息量翻倍。
- 取景时先 `isHidden=true` 把它藏起来 `frame`（贴合站厅），**再恢复显示**（显示不会改变既有取景）。
- 拍完 `move` 回原位并校验 `center.z` 回到原值（本例 9.5309）。

**兜底（统计不可用时）**：用 Pillow 在点面底图上叠半透明信息板，
中文字体 `C:\Windows\Fonts\msyh.ttc`（粗体 `msyhbd.ttc`），拿不到回退 simhei / simsun。
无论用哪种，**叠/显的数必须与实际取证值同口径**（写清「多边形数」还是「三角面数」）。

### 6. 打包 —— **一个 zip 搞定，别拆成多个**

**用户偏好：max 与 fbx 放同一个压缩包**（明确说过"不要再单独一个"），且 **FBX 要内嵌贴图**。

先把两种格式都备到同一个 staging 目录，再一次性打包：

```
打包源目录\_打包源文件\
├─ <name>.max          ← 贴图已改为 basename 相对路径，另存在此
├─ <name>.fbx          ← FBXExporterSetParam "EmbedTextures" true 后导出（贴图内嵌，单文件自包含）
└─ 贴图 ×594 (jpg/tga) ← .max 需要；与 FBX 内嵌的那份重复，但换来 .max 可直读、可二次改，值得
```

- **用 Python `zipfile`，不要用 `Compress-Archive`** — 实测 `Compress-Archive -Path "<dir>\*"` 会漏掉 `.max`（只打进贴图），且不报错
- 打完校验：`entries` 数、`with_subdir == 0`、`has max == True`、`has fbx == True`、`testzip() is None`
- **验证 FBX 是否真内嵌**：不能只看体积。扫二进制里的 JPEG SOI 标记 `ff d8 ff`（内嵌版通常上千个）和 `.tga` / `.jpg` 字符串；若只有几十个 SOI 说明只写了外引用
- 体积参考：270 MB 源文件 → 压缩后约 158 MB，**远低于 1G 上限**，ziplevel=9 即可（约 20 秒）

## 桌面环境注意事项

- 这台机器上 **Bash 的 PATH 是坏的**（`ls`/`grep`/`dirname` 全部 not found）。所有 shell 操作走 **PowerShell**
- PowerShell 的 stdout 回显经常被吞 → 一律 `$out | Out-File <log>` 再 `Read` 那个文件
- `Add-Type` 被安全策略拦截 → 需要 .NET 程序集（如 `System.Drawing` / `Compression`）时改用 **Python**
- `Remove-Item` 可能被沙箱拦（exit 1）→ 与其纠结删除，不如**换个干净的新目录**重建，或 `Move-Item` 归拢
- Python 用托管版：`C:\Users\Administrator.USER-20250812IR\.workbuddy\binaries\python\versions\3.13.12\python.exe`（已带 Pillow）
- **本机 `execute_maxscript` 的 MAXScript 解析坑（2026-09-21 实测，踩一次就记下来，别再重试）**：
  - **禁止 `min` / `max` 函数**（如 `min a b`）→ 直接报 `parse error`。围盒等改用分量比较：`if a.x < b.x do b.x = a.x` 等。
  - **`getSubTexmaps` 在本执行器里未定义**（报"需要函数或类，得到 undefined"）→ 枚举场景位图改用 `getClassInstances BitmapTexture`（返回所有位图实例）。
  - **`fn` 定义不能嵌在脚本块里**（被外层括号包住会 `parse error`）→ 用内联 `for` 循环，别定义函数。
  - **字符串字面量里不能有真实换行**（`"\n"` 会被当跨行字符串 → `parse error`）；多行输出用 ` | ` 分隔拼接，或 `(\"a\" + \"b\")` 连。
  - 已验证可用：`for ... where ... collect` 解析式、`+=` 自增、`superClassOf` / `isKindOf` / `polyop.getNumFaces` / `matchPattern` / `filenameFromPath` / `join`。
